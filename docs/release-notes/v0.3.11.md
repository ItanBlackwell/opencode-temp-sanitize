# Temp Sanitize v0.3.11

The first stable release of the independently maintained Temp Sanitize project. This release consolidates the improvements introduced since the original GFN-CIS v0.3.0 fork, rather than describing only the latest incremental change.

> **Automatic cleanup is disabled by default.** The plugin periodically discovers eligible files without deleting project data until automatic cleanup is enabled or manual deletion is explicitly confirmed.

## Desktop interface

- Added a dedicated **Settings → Temporary Files** page with native OpenCode controls.
- Added editable cleanup policy, validation, contextual tooltips, and a sticky Save/Cancel toolbar with an unsaved-changes indicator.
- Simplified the main settings page and grouped advanced settings, storage details, and operation history.
- Added localization for all 63 supported Desktop locales, including Russian.
- Improved button spacing, responsive wrapping, storage summary layout, and status messages.
- Separated preview and real cleanup: valid unsaved settings can be previewed without being persisted.

## Cleanup policy and manual control

- Replaced unconditional 48-hour deletion with configurable retention (7 days by default), a configurable scan interval (60 minutes by default), and explicit opt-in automatic deletion.
- Removed the separate preview-only switch. With automatic cleanup disabled, the same scheduler discovers candidates instead of deleting them.
- Added safe migration of old preview-only configurations; existing explicit choices are preserved.
- Added per-project soft size and file-count warning thresholds (2 GiB and 100,000 files by default). These never force eviction of recent or protected files.
- Added preview totals, file paths and sizes, individual selection, page selection, multi-page selection, and confirmed selective deletion of up to 500 files per operation.
- Added confirmed full manual cleanup using the saved policy.
- Added optional read-only legacy-root preview; loose root files remain outside the deletion scope.

## Safety and project isolation

- Extended agent shell routing to all three temporary-directory environment variables: TMPDIR, TEMP and TMP.
- Added process leases that protect the entire active project, including idle sessions.
- Preserved uploads, special filesystem entries, active leases and unrecognized directories.
- Hardened canonical-path and symlink/junction handling, including Windows short-path aliases.
- Revalidate selected files against the saved policy, age, identity, metadata, ancestry and active leases immediately before deletion. Reject stale snapshots and arbitrary deletion paths.
- Skip changed, missing, inaccessible or newly protected files rather than forcing deletion; report warnings in operation summaries.
- Keep project roots and avoid traversing link targets.

## Storage analysis and performance

- Added on-demand analysis of the complete OpenCode temporary tree, including uploads, loose root files and unrecognized directories.
- Show total logical size, file counts, per-directory statistics, protection status, scan warnings and the actual canonical temporary root.
- Added server-side pagination for both cleanup candidates and Storage Overview (50 entries per page).
- Load aggregate summaries separately from detail pages; switching pages does not rescan storage.
- Retain one candidate snapshot and one storage inventory in memory, replacing old snapshots instead of maintaining historical file lists.
- Limit operation history to 50 in-memory summaries; avoid persistent scan databases and per-file log floods.

## Cleanup notification

- Added the approved amber trash-ring indicator in the lower-left Desktop area, with a theme-aware glyph.
- The indicator appears only when automatic cleanup is off, the indicator preference is enabled, and the saved-policy snapshot contains eligible files.
- Hover displays the candidate count and total logical size. Clicking opens settings and expands the candidate list.
- Added a default-enabled visibility setting, including migration for existing installations.
- Designed positioning to coexist with Usage Dashboard and the native update control without moving or restyling either; use a separate row where possible when space is limited.
- Poll only a compact status response; the indicator itself does not scan storage or create disk caches.

## Portable installation, updates and recovery

- Added a bundled Windows portable package that requires no separate npm dependency installation.
- Added Install.cmd, Update.cmd, Uninstall.cmd and Rollback.cmd; honor OPENCODE_CONFIG_DIR and preserve saved settings.
- Install directly into the global plugin directory, with atomic per-file replacement, recovery backups and no persistent installer worker.
- Added Desktop update modes: Notify (default), Automatic and Manual.
- Check stable GitHub Releases, validate release assets and verify the ZIP SHA-256 before installation.
- Distinguish repositories without published stable releases from actual HTTP/network/IPC failures, with diagnostic codes.
- Added version compatibility checks between GUI and server, and fixed asynchronous RPC handlers.

## Plugin maintenance

- Reclaim strictly recognized empty lease markers and temporary settings writes belonging to confirmed dead processes.
- Recover abandoned installer stages, update downloads and atomic swap debris conservatively.
- Normally retain only the two newest complete recognized rollback payloads; preserve unknown or incomplete historical recovery data.
- Bound recurring diagnostics per server process and release in-memory state on shutdown.

## Project and validation

- Established an independent repository with main as its default branch, updated project documentation, and retained the original MIT license and GFN-CIS copyright alongside attribution for ItanBlackwell's modifications.
- Added regression coverage for cleanup, storage pagination, settings migration, localization, indicator placement/lifecycle, updater behavior, and installer recovery.
- The release workflow passed the complete 130-test regression suite, Windows portable build, packaged RPC smoke test and Windows installer smoke test. Live Desktop rendering with Usage Dashboard and end-to-end installation of a newer stable release still require real-world verification.

## Install

Requires OpenCode 2.2+ with the experimental Desktop GUI and plugin RPC APIs for the full experience.

1. Download **Temp-Sanitize-Portable-0.3.11.zip** from the assets below.
2. Verify the ZIP against **SHA256SUMS.txt**.
3. Extract it and run Install.cmd.
4. Restart OpenCode Desktop and its server, then open Settings → Temporary Files.

Deletion is permanent; installer rollback restores plugin files, not deleted temporary data. Active projects, uploads and unowned root data can still occupy storage. Candidate memory usage depends on the number of eligible files; pagination limits renderer and RPC load, not filesystem traversal.
