# Temp Sanitize v0.3.12

Extend the lifetime of temporary files you want to keep without copying, moving or deleting them. This release builds on v0.3.11 and adds convenient retention controls, safer timestamp renewal and a compact project attribution footer.

## New: Extend retention

- Click the clock/history icon next to a regular file in the cleanup candidate list to renew its last-access timestamp.
- Select files across candidate pages and use **Extend retention** to renew up to 500 files in one operation.
- Only the filesystem access timestamp (atime) is renewed to the current server time; the file contents are not changed and the modification time is preserved within filesystem timestamp precision.
- The existing age-based policy applies from the renewed access time. A file becomes eligible again after the configured retention interval if it is not used again.
- Successfully renewed files disappear from the candidate list immediately. Candidate counts, logical reclaimable size and the sidebar cleanup indicator are refreshed.
- The renewed timestamp survives plugin restarts without a separate exclusion list, database or configuration file. Total storage usage does not decrease because no data is deleted.
- No deletion confirmation is needed for renewal. The action is disabled while settings are unsaved, another UI operation is running or a deletion confirmation is open.

## Safety and error handling

- The server accepts only candidate IDs from the current server-owned snapshot; stale snapshots and invalid, duplicated or oversized selections are rejected.
- The saved cleanup policy, age, file identity and metadata, canonical ancestry and project leases are rechecked before renewal.
- Timestamp renewal uses an opened file descriptor rather than relying solely on the original path. Symbolic links and files with multiple hard links are excluded to avoid changing an unrelated target.
- Missing, changed, protected or inaccessible files are skipped and reported as warnings. Failed entries remain visible until the next scan.
- The candidate snapshot ID is rotated after the operation to invalidate stale selections. Existing storage analysis remains available because renewal does not remove data.
- Filesystem permissions and timestamp resolution still apply. Renewal is not a permanent exemption from cleanup and cannot guarantee protection against concurrent external writers.

## Desktop interface

- Added an individual renewal icon with tooltip and a neutral bulk action beside the existing selected-file deletion controls.
- Added operation feedback showing how many files were renewed and how many warnings occurred.
- Candidate tooltips show the last-used time, based on the newer of access and modification timestamps.
- Added translated labels, descriptions and feedback for the new feature in all 63 supported Desktop locales.
- Added a discreet copyright and MIT license footer in the Temporary Files settings page, with attribution to ItanBlackwell and the original author GFN-CIS.
- Added a clickable **GitHub** repository link alongside the copyright, using OpenCode's external-browser API where available and a standard HTTPS anchor as fallback.

## Validation and compatibility

- Added six retention regression tests covering timestamp and content preservation, restart persistence, renewed eligibility, batch operations, indicator updates, invalid selections, changed files, project leases and link safety.
- Extended packaged RPC smoke tests to exercise retention renewal and subsequent cleanup.
- Added the complete Linux regression suite to the portable CI workflow.
- The pre-release branch passed all 136 Linux tests and 100 targeted Windows tests. One Unix symbolic-link test was intentionally skipped on Windows. Portable bundling, packaged RPC and Windows installer smoke tests passed.
- Live rendering and external-browser navigation inside OpenCode Desktop have not been manually verified by CI.
- Existing automatic-cleanup defaults, saved settings and update modes remain unchanged.

## Install or update

Requires OpenCode 2.2+ with the experimental Desktop GUI and plugin RPC APIs for the full experience.

- Existing installations: use the plugin's update controls or run Update.cmd.
- New installations: download **Temp-Sanitize-Portable-0.3.12.zip**, verify it against **SHA256SUMS.txt**, extract and run Install.cmd.
- Restart OpenCode Desktop and its server after updating so that both plugin components use the same version.
